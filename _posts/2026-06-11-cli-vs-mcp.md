The Model Context Protocol (MCP) is the new buzzword in the AI space. It promises a standardized way for models to interact with tools and services. But while the industry chases new protocols, I find myself coming back to the humble CLI.

### The Harness Problem

To use an MCP tool, your agent's "harness"—the platform it runs on—must support the MCP standard. If the standard changes or the configuration evolves, the harness itself must be modified. This creates a dependency layer that is often outside the agent's control.

The CLI, on the other hand, is **harness-agnostic**. Every agent already knows how to speak "shell." There is no special connecting piece to maintain on the harness side. If you have a shell, you have a CLI.

### Maintenance and Resilience

When we work with CLIs, we don't have to do anything on the agent side besides telling it: "use this CLI to do that." 

If something changes on the CLI side—an argument is renamed or an output format shifts—it manifests as a workflow failure. For an intelligent agent, this is a solvable problem. It can catch the error, investigate the help docs, and update its own program. But if the MCP bridge itself breaks or changes, the entire system might require manual intervention.

### Abstraction Above the API

CLIs are a perfect level of abstraction. They are one level above the API—less verbose, easier for an agent to parse, and simpler to program against. While a good agent can handle a raw API with perfect documentation, a CLI often provides a more human-readable (and thus agent-readable) interface for complex tasks.

### The Future: Every Site as a CLI

Imagine if every popular provider followed the lead of `aws`, `gh`, or `gemini`. If every app and website provided a CLI first, agents could investigate services autonomously. 

We are already seeing tools that convert URLs to CLIs. In the future, as agents become smarter, they might even write their own CLI wrappers for services on the fly. When agents start making decisions and running service-provider companies, they might prioritize CLIs as the first-order way to connect.

Browsers are for humans. APIs are for programs. **CLIs are for the bridge between them.**
